# 第 12 关初学者教程与示例代码同步改造设计

## 目标

将第 12 关改造成电子小白可以独立完成的联网入门课。读者应能先成功连接 2.4 GHz Wi-Fi，再理解网络授时，最后取得并解析一份天气数据。教程和 `code/12_wifi_weather/` 的三个实验源码必须使用同一套术语、步骤和预期日志。

## 范围

- 重写 `book/12_WiFi连接管理与HTTP天气时钟.md`。
- 修正 `01_wifi_sta_connect.c`、`02_sntp_time_sync.c` 和 `03_http_weather_clock.c`。
- 不修改 `main/app_main.c`、显示驱动、硬件配置或其他关卡。
- 本关只验证串口侧的联网、对时与天气数据获取；不宣称天气已经显示在 LCD 上。

## 教学结构

1. **先跑通**：明确硬件不需要额外接线，说明只支持 2.4 GHz Wi-Fi，指出填写 SSID 与密码的位置，并用成功日志定义每个实验的完成条件。
2. **再建立直觉**：用手机、路由器和快递地址解释 STA、IP、DNS、HTTP、JSON 与 SNTP。每个术语先说它解决的生活问题，再给出在本关的实际作用。
3. **逐层组合**：实验 1 仅处理 Wi-Fi；实验 2 在网络就绪后请求时间；实验 3 在前两者之上取得天气 JSON。每层都给出最小关键代码、逐行解释和预期串口输出。
4. **最后排错和复习**：提供密码错误、5 GHz、无 IP、DNS/HTTP 失败和 JSON 字段不存在的现象—原因—操作表；加入主动回忆题与可操作的经纬度练习。

## 源码设计

### 实验 1：Wi-Fi

- 使用 STA 模式，并在 `IP_EVENT_STA_GOT_IP` 发生后才宣布网络可用。
- 对断连设置有限重试；失败时设置失败事件位，避免永远等待。
- 输出连接、重试、获得 IP 与失败原因，帮助读者用日志定位阶段。

### 实验 2：SNTP

- 复用清晰的 Wi-Fi 成功判定。
- 使用 ESP-IDF 6 的 `esp_netif_sntp` 接口启动网络授时，并在规定等待时间内检查同步状态。
- `TZ=CST-8` 只负责把 UTC 格式化为中国标准时间；时间准确度受网络、服务器和本地振荡器等因素影响，不使用“毫秒级精准”承诺。

### 实验 3：HTTP 天气

- 请求 Open-Meteo 的现行 `current` 参数：`temperature_2m`、`wind_speed_10m`、`weather_code`。
- 以固定大小接收缓冲区收集 HTTP 响应，并显式报告溢出、请求失败和非 200 状态码。
- 用 `cJSON_IsNumber` 验证字段类型，最后释放根节点。
- 把 WMO 天气代码翻译成少量中文状态，避免只打印无意义数字。
- HTTP 仅用于教学演示。教程会说明生产设备应迁移到 HTTPS 并启用服务器证书验证。

## 验证标准

- 三个示例文件可以分别切换到 `main/app_main.c` 并通过 `idf.py build`。
- 教程中的源码链接、函数名、字段名和日志文字均可在对应示例中找到。
- Markdown 无断链，并包含成功日志、失败排查与复习练习。
- 验证层级写清楚：构建成功不等于开发板已经连接实际 Wi-Fi 或可访问外网；实际设备验证需由烧录和串口日志确认。

## 不做的事

- 不引入配网界面、NVS 保存 Wi-Fi 密码、LCD 天气界面或 MQTT。
- 不更改已有屏幕排线、显示旋转、引脚和资源文件。
